## 一、核心修复

### 1.1 MIDI 解析 — Tempo Map 动态变速支持

**文件**: `video/convert_score.py`

**问题**: 原代码用最后一个 `set_tempo` 值计算所有音符时长，导致有 ritardando（渐慢）的 MIDI 文件时长被放大（bad_apple_explict.mid：428.5s → 215.5s，实际 3分38秒）。

**修复**: 实现完整的 tempo map 分段计算——收集所有 `set_tempo` 事件，预计算每个事件 tick 的绝对毫秒值（累积微秒→末次除一次，消除截断误差），时间切片函数改用绝对 ms 差值。

### 1.2 频率自适应转换（方案D）

**文件**: `video/convert_score.py`

**问题**: 钢琴 MIDI 的低频段（0~200Hz）在蜂鸣器上表现极差（"喉咙咯痰"声），208 个低频音符需处理。

**实现**: 新增 `transpose_chords()` + `_transpose_chord()` 函数：
- Step 1: 各声部独立升八度至 [min_freq, max_freq] 区间
- Step 2: 碰撞消解——检测声部间频率重复，对冲突声部再升八度

新增 CLI 参数：
- `--min-freq 200` （默认）
- `--max-freq 3000` （默认）
- `--no-transpose` （关闭转换）

### 1.3 编译错误修复

- `video_stream.c`: `BAD_APPLE_CHORD_COUNT` → `BAD_APPLE_SCORE_CHORD_COUNT`（与生成的头文件宏名统一）
- `User/main.c`: `ms_counter()` 前向声明问题
- `User/stm32f10x_it.c`: 移除重复的 `SysTick_Handler`

## 二、新增功能

### 2.1 三蜂鸣器真和弦（v2.0 核心）

**文件**: `Hardware/audio_pwm.h`, `Hardware/audio_pwm.c`

- 新增 `MusicChord` 结构体（f0/f1/f2/dur，三声道）
- TIM1→PA3 作为第三声道（复用 APB2 总线 `timer_config`）
- `AudioPWM_StartChord()` / `AudioPWM_PlayChord()` 和弦 API
- `VoiceMode` 枚举 + `SetVoiceMode()` / `GetVoiceMode()` — 运行时切换 1CH→2CH→3CH
- `AudioPWM_Update()` 自动检测 `is_chord` 标志，兼容 MusicNote/MusicChord

### 2.2 convert_score.py — 多声道输出

**文件**: `video/convert_score.py`

- `--voices 1|2|3` 参数：1=MusicNote（兼容旧格式），2/3=MusicChord（和弦格式）
- `_parse_midi_time_slice_multi()`：从高到低取 N 个音，不足补 0
- `generate_chord_header()`：生成 `MusicChord[]` 格式头文件
- `--count-only` 增加声道分布统计（0音/1音/2音/3音各多少）

### 2.3 video_stream.c — 单字节命令识别

**文件**: `Hardware/video_stream.c`

- USART IDLE 中断中区分 `received==1 && !=0xAA` → 命令模式
- `_process_cmd()`：支持 `h`(和声) / `+`/`−`(音量) 热切换
- `#if defined(BAD_APPLE_SCORE_CHORD_COUNT)` 自动选择 PlayChord/PlayScore

### 2.4 pc_streamer.py v2.2 — 交互式视频推流

**文件**: `video/pc_streamer.py`

- 后台键盘监听线程：`[h]`和声 `[+/-]`音量 `[s]`状态 `[q]`退出
- 启动前和声/音量预设
- 帧间隙发送单字节命令到 MCU
- 进度条显示实时和声模式+音量
